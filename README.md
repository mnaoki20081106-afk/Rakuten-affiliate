# 🤖 Threads × 楽天アフィリエイト 完全自動運用テンプレート

Threads・楽天・Claude を組み合わせて、**最大 10 アカウント規模の SNS 運用をまるごと自動化**する
オープンソーステンプレートです。**フォークして自分のリポジトリで動かせます。**

- 🖥 **サーバー不要** — GitHub Actions と GitHub Pages だけで完結します（外部ホスティング契約なし）
- 🔐 **トークンはリポジトリに保存しません** — すべて GitHub Secrets に暗号化して保存されます
- 📱 **管理はブラウザだけ** — スマホ・タブレットからでも設定できます（ターミナル不要）

```
                        ┌───────────────────────┐
  あなた ──ブラウザ──►  │  管理画面（GitHub Pages）│
                        └───────────┬───────────┘
                          ┌─────────┴──────────┐
                          ▼                    ▼
              🔓 非機密（テーマなど）      🔐 機密（トークン・APIキー）
                config/accounts.json      ブラウザ内で暗号化 → GitHub Secrets
                          │                    │
                          └────────┬───────────┘
                                   ▼
                     GitHub Actions が毎日自動で実行
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        ▼                          ▼                          ▼
   毎日 23:00                翌日の予約時刻              月・水・金 19:30
   商品リサーチ・投稿生成      Threadsへ自動投稿            過去のバズを再投稿
   翌日の時間割を作成         ＋PRリンクをコメント
```

## 🔐 セキュリティの考え方（最初にお読みください）

このリポジトリは**公開（Public）**での利用を前提としています。つまり、
**リポジトリ内のファイルは世界中の誰でも読めます。**

そのため、機密情報は**ファイルには一切保存しません。**

| 情報の種類 | 保存場所 | 誰が見られるか |
| --- | --- | --- |
| アカウント名・テーマ・キーワード | `config/accounts.json` | 誰でも（非機密なので問題ありません） |
| **Threadsアクセストークン** | **GitHub Secrets** | **誰も見られません**（あなたも再表示できません） |
| **Claude APIキー / 楽天APIキー** | **GitHub Secrets** | **誰も見られません** |

管理画面でトークンを入力すると、**あなたのブラウザの中で暗号化されてから**送信されます。
暗号化には GitHub が公開している鍵を使い、復号できるのは GitHub だけです。
平文のトークンは、ネットワークにもリポジトリにも一切残りません。

> 💡 各アカウントのトークンは `THREADS_TOKEN_{アカウントIDの大文字}` という名前で保存されます。
> 例: アカウントIDが `beauty_lab` → シークレット名は `THREADS_TOKEN_BEAUTY_LAB`
> この名前は管理画面が自動で決め、実行するワークフローも自動で参照するので、
> あなたが名前を意識する必要はありません。

# 📖 セットアップ手順

所要時間は **60〜90分** ほどです。上から順に進めてください。
**最初は 1 アカウントだけ**で通すことを強くおすすめします。

## STEP 1️⃣ このリポジトリをフォークする

「フォーク」とは、他人のリポジトリを**自分のリポジトリとしてコピー**することです。

1. このページの**右上にある `Fork` ボタン**を押します
2. `Owner` が自分のアカウントになっていることを確認します
3. `Repository name` はそのままで構いません
4. **`Copy the main branch only`（mainブランチのみコピー）にチェックが入ったまま**にします
5. 緑の **`Create fork`** ボタンを押します

数秒で `https://github.com/あなたの名前/Rakuten-affiliate` ができあがります。
**以降の作業はすべて、フォークした自分のリポジトリで行ってください。**

> ⚠️ フォークしたリポジトリは **Public（公開）のまま**で問題ありません。
> トークンはファイルに保存されないためです。
> なお GitHub Pages は Public リポジトリなら無料で使えます。

---

## STEP 2️⃣ GitHub Actions に書き込み権限を与える

自動処理が「投稿予定表」をリポジトリに保存できるようにする設定です。**これをしないと動きません。**

1. フォークした自分のリポジトリで **`Settings`（設定）**タブを開く
2. 左メニューを下にスクロールし、**`Actions` → `General`** をクリック
3. ページ最下部の **`Workflow permissions`** を探す
4. **`Read and write permissions`（読み取りと書き込みの権限）**を選ぶ
5. **`Save`** ボタンを押す

続けて、フォーク直後は自動処理が停止しているので有効化します。

6. 上部の **`Actions`** タブを開く
7. **`I understand my workflows, go ahead and enable them`**（緑のボタン）を押す

---

## STEP 3️⃣ 管理画面を公開する（GitHub Pages）

1. **`Settings`** タブ → 左メニューの **`Pages`** をクリック
2. **`Build and deployment`** の **`Source`** を **`Deploy from a branch`** にする
3. **`Branch`** を次のように設定します
   - 左のプルダウン: **`main`**
   - 右のプルダウン: **`/(root)` から `/docs` に変更** ← ここが重要です
4. **`Save`** を押す
5. **1〜2分待ってページを再読み込み**すると、上部に公開URLが表示されます

```
https://あなたのGitHubユーザー名.github.io/Rakuten-affiliate/
```

📱 このURLをスマホのホーム画面に追加しておくと、アプリのように使えて便利です。

> ❓ **このURLは誰でも開けますが、安全です。**
> 中身を見るにはあなた自身のトークンが必要で、そのトークンはページのソースには含まれず、
> 入力した人のブラウザの中にしか保存されません。他人が開いても何も表示されません。

---

## STEP 4️⃣ 管理画面用のトークン（PAT）を作る

管理画面が、あなたの代わりにリポジトリを読み書きするための鍵です。

1. GitHub右上のアイコン → **`Settings`**（リポジトリの設定ではなく**アカウントの設定**です）
2. 左メニューを一番下までスクロール → **`Developer settings`**
3. **`Personal access tokens`** → **`Tokens (classic)`**
4. **`Generate new token`** → **`Generate new token (classic)`**
5. 以下のように入力します
   - **Note**（メモ）: `sns-admin`
   - **Expiration**（有効期限）: `90 days` など（切れたら作り直します）
   - **Select scopes**: **`repo`** の左のチェックボックスをオンにする ← **これだけでOK**
6. ページ最下部の **`Generate token`** を押す
7. **`ghp_` で始まる文字列が表示されます。必ずコピーしてください**

> ⚠️ **この画面を閉じると二度と表示されません。** メモアプリに貼り付けておいてください。
> （作業が終わったらメモは削除してください）

**なぜ `repo` 権限だけでよいの？**
`repo` には「設定ファイルの読み書き」と「シークレットの暗号化保存」の両方が含まれるためです。

---

## STEP 5️⃣ 管理画面にログインする

1. STEP 3 で表示された公開URLをブラウザで開きます
2. ログイン画面で次を入力します
   - **Personal Access Token**: STEP 4 でコピーした `ghp_...`
   - **オーナー名 / リポジトリ名**: URLから自動入力されます（違っていれば直してください）
   - **ブランチ**: `main`
3. **`接続する`** を押します

ログインすると **「セットアップの進み具合」**が表示されます。
以降はこのチェックリストが全部緑になるまで進めていけばOKです。

> 🔓 使い終わったら画面右上の **`切断`** を押すと、保存されたトークンが削除されます。
> 共用の端末を使うときは必ず切断してください。

## STEP 6️⃣ APIキーを登録する

管理画面の **`APIキー`** タブを開き、以下の4つを登録します。
**入力欄に貼り付けて「暗号化して保存」を押すだけ**です。

### ① Claude APIキー（`ANTHROPIC_API_KEY`）

投稿文と「ターゲットの悩み」の生成に使います。

1. [Anthropic Console](https://console.anthropic.com/) にアクセスしてアカウント作成
2. **`Billing`** から少額（$5〜10程度）のクレジットを購入します
3. **`API Keys`** → **`Create Key`** で `sk-ant-...` を発行してコピー

> 💰 **費用の目安**: 1アカウント7投稿で1日14回のAPI呼び出しです。
> **必ず1アカウントから始めて**、Console の `Usage` で実際の日額を確認してから増やしてください。

### ② 楽天アプリID（`RAKUTEN_APP_ID`）

商品検索に使います。

1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/) に楽天会員でログイン
2. **`アプリID発行`** をクリック
3. アプリ名（例: `sns-auto`）とURL（フォークしたリポジトリのURLでOK）を入力
4. 発行された**数字の羅列**をコピー

### ③ 楽天アフィリエイトID（`RAKUTEN_AFFILIATE_ID`）

投稿に貼るアフィリエイトリンクの生成に使います。

1. [楽天アフィリエイト](https://affiliate.rakuten.co.jp/) にログイン
2. 表示されているアフィリエイトIDをコピー

### ④ ワークフロー用トークン（`WORKFLOW_TOKEN`）

**これが無いと自動投稿が動きません。**
毎日「翌日の投稿時刻表」を書き換える必要があり、それには特別な権限が要るためです。

1. STEP 4 と同じ手順でトークンをもう1つ作ります
2. ただし今回は **`repo`** に加えて **`workflow`** にも**チェックを入れます**
3. 発行された `ghp_...` を管理画面に貼り付けて保存

> 📝 **管理画面を使わず手動で登録することもできます。**
> リポジトリの `Settings` → `Secrets and variables` → `Actions` →
> `New repository secret` から、上記の名前（`ANTHROPIC_API_KEY` など）で登録してください。
> 管理画面から登録した場合とまったく同じ結果になります。

## STEP 7️⃣ Threadsアカウントを連携する

**「Threadsでログイン」ボタンを押すだけ**で連携できます。トークンのコピペは不要です。
そのための準備として、**Metaでアプリを1つだけ作ります**（何アカウント運用しても1回で済みます）。

### ① Metaでアプリを作り、この管理画面に登録する

管理画面の **「APIキー」タブ → 「Threads連携の準備」→「設定をはじめる」** を押すと、
**1画面に1つの作業だけ**が表示されるウィザードが開きます。以下はその内容です。

**1. Metaでアプリを作る**

1. [Meta for Developers](https://developers.facebook.com/) にログインする
2. **マイアプリ** → **アプリを作成** を押す
3. ユースケースの選択で **「Threads APIの使用」** を選ぶ
4. アプリ名（何でも構いません）と連絡先メールアドレスを入力して作成する

**2. コールバックURLを登録する**

アプリのダッシュボードから **Threads API の設定画面（Settings）** を開き、
**コールバックURL（Redirect URI）** の欄に次のURLを貼り付けて保存します。

```
https://あなたのGitHubユーザー名.github.io/Rakuten-affiliate/
```

一字一句そのままにしてください（末尾の `/` も必要です）。
管理画面に**コピーボタン**が用意されています。

**3. アプリIDとアプリシークレットを控える**

**同じ設定画面（Settings）** に表示されています。

| 項目 | 見た目の目安 |
| --- | --- |
| アプリID（Client ID） | 数字だけが15〜17桁ほど |
| アプリシークレット（Client Secret） | 英数字が30文字ほど。伏せ字なので「表示」を押す |

どちらも管理画面のウィザードに貼り付けて保存します。

**4. Threadsテスターを追加する**

同じ設定画面の **「Threadsテスターの追加/削除」** から、連携したいThreadsアカウントの
**ユーザーネーム**を追加します。追加直後は **Pending（保留中）** と表示されます。

**5. スマホで招待を承認する**

ここが忘れやすい手順です。**パソコンではなくスマートフォン**で操作します。

1. Threadsアプリを開く（追加したアカウントでログインした状態）
2. **設定** → **アカウント** → **ウェブサイトのアクセス許可**
3. 開発者からの**招待を承認**する

これで Pending が解除され、連携できるようになります。

### ② アカウントを連携する

1. **「アカウント管理」タブ** でアカウントを作る（テーマなどを入力）
2. そのアカウントの **「Threadsでログイン」** ボタンを押す
3. **Threads自身のログイン画面**が開くので、いつもどおりログインして「許可」を押す
4. 管理画面に戻ると、**トークンが自動で発行・暗号化保存**されます（1〜2分）

> 🔒 **パスワードは管理画面に入力しません。** ログインはThreadsのページで行われ、
> こちらに渡るのは「許可されたことを示す使い捨ての引換券」だけです。
> 引換券からトークンへの交換はGitHub Actionsの中だけで行われ、
> アプリシークレットがブラウザに渡ることもありません。

> ⏰ 有効期限（60日）は**毎週自動で延長**されます。手作業での更新は不要です。

### 手作業でトークンを登録することもできます

アカウント編集画面の「トークンの取得のしかた」から、従来どおり手動でも登録できます。

### あとでライブモードにする場合

他の人にも使ってもらう段階になったら、本審査を通してライブモードにします。
そうするとテスター追加が不要になります。

| | 開発モード（最初はこちら） | ライブモード |
| --- | --- | --- |
| 連携できるアカウント | テスターに追加したアカウントのみ | 制限なし |
| 必要な手続き | なし（アカウントごとにテスター追加） | Meta の本審査 |
| 向いている場面 | 自分のアカウントを運用する | 他人にも使ってもらう |

審査では**プライバシーポリシーと利用規約のURL**を求められます。
このリポジトリに**ひな形を用意してあります**（運営者名と連絡先の記入が必要です）。

```
https://あなたのGitHubユーザー名.github.io/Rakuten-affiliate/privacy.html
https://あなたのGitHubユーザー名.github.io/Rakuten-affiliate/terms.html
```

管理画面の「Threadsアプリの設定」→「開発モードのままで大丈夫？」を開くと、
このURLがコピーボタンつきで表示されます。

このほか、審査ではビジネス認証や実際の利用の様子を撮った動画などを求められる場合があります。
要件は変わるため、申請時にMetaの画面の案内を確認してください。

## STEP 8️⃣ 動作確認して自動運転を開始する

### ① まず空撃ちテスト（費用ゼロ・投稿されません）

1. リポジトリの **`Actions`** タブを開く
   （※スマホの場合は必ずブラウザを「デスクトップ表示」に。でないとボタンが出ません）
2. 左メニューの **`Batch Generator`** をクリック
3. 右側の **`Run workflow`** をクリック
4. **`dry_run` にチェックを入れて** **`Run workflow`**
5. 数分後に緑のチェック ✅ が付けば成功です

### ② 本番テスト（実際に生成されます・API費用が発生します）

1. 同じく **`Batch Generator`** → **`Run workflow`**（今度は `dry_run` の**チェックなし**）
2. 完了したら管理画面の **`ダッシュボード`** を開きます
3. 明日の7件分の**投稿時刻と本文**が並んでいれば成功です
4. **本文の品質をここで必ず確認してください**

### ③ 1件だけ実際に投稿してみる

内容に納得できたら、`Actions` タブの **`Publisher`** を **`Run workflow`** で手動実行します。
自分のThreadsアプリを開いて、**投稿とコメント欄のPRリンクの両方**が付いているか確認してください。

### ④ あとは放置

ここまで通れば完全自動です。

| いつ | 何が起きるか |
| --- | --- |
| 毎日 **23:00** | 翌日分の商品リサーチ・投稿文生成・時間割の作成 |
| 翌日 **7:00〜23:00** の7回 | 予約時刻ぴったりに自動投稿（＋PRリンクをコメント） |
| 月・水・金 **19:30** | 過去1週間で伸びた投稿を再投稿（その日の8件目） |
| 月曜 **04:00** | Threadsトークンの有効期限を自動で延長（手作業不要） |

# ⚙️ 仕組みの詳細

## 前日バッチ（毎日 JST 23:00）

登録済みの全アカウントを **1アカウントずつ順番に**処理します。

1. **リサーチ（重複防止）** — 楽天APIで上位50件を取得し、
   **過去14日以内に同じアカウントで紹介した商品を除外**。
   残った候補から**ランダムに必ず7件**選びます。
2. **悩み生成** — Claudeに商品情報とテーマを渡し、ターゲットの具体的な悩みを推測させます。
3. **投稿生成** — プロンプトの `{ジャンル}` `{ターゲットの悩み}` `{商品名}` `{口調}` を置換して送信。
   複数パターンのうち **「伸びる確率：〇〇％」が最も高いものの本文だけ**を採用します。
4. **時間割の作成** — 7:00〜23:00 を7枠に等分し、各枠に **±15〜30分のゆらぎ**を付与。
   **売れ筋ランキング上位の商品をゴールデンタイム（朝7〜8時台／夜20〜22時台）に優先配置**します。
5. **予約の登録** — 決まった時刻ぴったりに起動するよう、配信用ワークフローを自動生成します。
   1ファイルにつき予約は60件までというGitHubの制限があるため、
   **超える場合はファイルを自動分割**します（10アカウント×7投稿にも対応）。

## 当日の配信

予約時刻に起動し、**待たずにすぐ**投稿します。
親投稿の直後に、コメント欄へ**楽天アフィリエイトURL＋「※PR」**を自動で追加します。

## 再投稿（月・水・金 19:30）

過去1週間の履歴からアカウントごとに**いいね数の上位3件**を抽出し、
**月曜＝1位／水曜＝2位／金曜＝3位**の順に、元の本文のまま再投稿します。

# 🔄 トークンの自動更新

Threads の長寿命トークンは **60日で失効**します。失効すると全アカウントの投稿が止まるため、
**毎週自動で期限を延長する仕組み**（`Token Refresh` ワークフロー）を用意しています。

## 何が起きるか

| いつ | 何をするか |
| --- | --- |
| 毎週 **月曜 04:00**（JST） | 登録済みの各トークンを Threads API で更新し、期限を約60日先へ延ばす |
| 更新のたび | 新しいトークンを**暗号化して GitHub Secrets に上書き保存**する |
| 毎回 | 残り日数を `data/token_status.json` に記録し、管理画面に表示する |

**あなたが手を動かす必要はありません。** トークンの値がどこかに平文で書き出されることもなく、
更新後の値も暗号化されたまま Secrets に入ります。

## なぜ毎週なのか

Threads API の仕様上、更新できるのは「発行から24時間以上経過し、まだ失効していない」トークンだけです。
毎週実行すれば、**失効までに8回以上のやり直しの機会**があるため、
一時的な通信エラーで1〜2回失敗しても自動的に回復します。

## 状態の確認方法

管理画面の **`アカウント管理`** タブと **`APIキー`** タブに、各アカウントの残り日数が表示されます。

- 🟦 **残り 58 日** — 正常です
- 🟠 **残り 9 日** — 更新が止まっている可能性があります
- 🔴 **期限切れ** — 手動での取り直しが必要です

残り14日を切ると、**ダッシュボードの一番上に赤い警告**が出ます。

## うまくいかないときは

1. まず手動で更新を試します
   `Actions` タブ → **`Token Refresh`** → **`Run workflow`**
   （`force` にチェックを入れると、直近に更新済みでも強制的に実行します）
2. それでも失敗する場合、実行ログに理由が出ます

| ログのメッセージ | 意味と対処 |
| --- | --- |
| `WORKFLOW_TOKEN が未設定です` | STEP 6 ④ の `WORKFLOW_TOKEN` を登録してください |
| `THREADS_TOKEN_XXX が未登録です` | そのアカウントのトークンが未登録です（STEP 7） |
| `Session has expired` などの 400 系 | **完全に失効しています。** STEP 7 の手順で取り直してください |
| `403 Forbidden` | `WORKFLOW_TOKEN` に `repo` 権限が付いているか確認してください |

> 💡 60日以上まったく動かさずに放置すると失効します。その場合だけ STEP 7 をやり直してください。

# 🛠 困ったときは

| 症状 | 原因と対処 |
| --- | --- |
| バッチは成功するのに翌日投稿されない | `WORKFLOW_TOKEN` が未登録、または `workflow` 権限が付いていない |
| Actionsが赤い❌になる | ログを開くとエラー内容が読めます。多くはAPIキーの入れ間違いです |
| `Run workflow` ボタンが出ない | スマホのブラウザが「モバイル表示」。デスクトップ表示に切り替えてください |
| 投稿だけ全部失敗する | Threadsトークンの失効。まず `Token Refresh` を手動実行し、駄目なら「Threadsでログイン」から再連携 |
| 「Threadsでログイン」が押せない | 「APIキー」タブの「Threadsアプリの設定」が未完了です |
| 連携でリダイレクトのエラーが出る | Metaに登録したリダイレクトURLが管理画面の表示と一致しているか確認 |
| 管理画面が「未登録」のまま | 管理画面のトークンに `repo` 権限が付いているか確認してください |
| 商品が毎日似てしまう | 管理画面の「アカウント管理」で検索キーワードを3〜5個に増やしてください |

**設定を変えたいとき**は、すべて管理画面から行えます（`共通設定` タブで投稿数・活動時間帯・
ゆらぎ幅・重複除外日数などを、`プロンプト` タブで投稿文の指示を変更できます）。

**管理画面のデザイン規約**

管理画面は白と黒を基調としたミニマル・ソリッドなデザインで統一しています。
外部のCSSフレームワークは使わず、`docs/style.css` の 1 ファイルで完結しています
（角丸・影・グレーといった既定値との衝突を避けるため）。

| 項目 | ルール |
| --- | --- |
| 配色 | 背景は白 `#FFFFFF`、文字・線・アイコンは黒 `#000000`。グレーは使わない |
| 形状 | 角丸なし（`border-radius: 0`）、影なし（`box-shadow` なし） |
| ボタン | メインは黒背景に白文字、サブは白背景に黒枠・黒文字 |
| 入力欄 | 枠で囲わず、太い黒の下線のみ |
| 文字 | サンセリフ体。見出しは大きく太く、余白は広めに取る |
| 例外色 | 赤 `#D50000`＝エラー・必須・削除／水色 `#0077B6`・`#00A5E0`＝リンク・選択中・進行中 |

例外色は「白黒だけでは状態が伝わらない」場面に限って使い、白背景でのコントラスト比が
4.5:1 以上になる値を選んでいます。これらの規約は `tests/test_design_system.py` が自動で検査します。

**注意事項**

- cron は**デフォルトブランチ（main）のものだけ**が有効です。
- cron は **UTC 基準**です（`0 14 * * *` が JST 23:00）。
- GitHub Actions の cron は**数分〜十数分遅れる**ことがあります。
  取りこぼしを拾うため、配信側に猶予の「窓」を設けています。
- `config/accounts.json` に機密情報が混入していないかは、
  `tests/test_repository_security.py` が自動で検査します。
